Appendix: the pain point, and the realistic migration path

The pain tuning doesn't remove

GC pause frequency/duration is tunable. The category is not.

Spark under pressure: a silent executor OOM-kill, then the whole stage retries.

DataFusion under pressure: an unbounded pool swap-thrashed 4.5+ hours, no output. Bounded, it instead fails one query, exactly: "HashJoinInput[5] ... 197.9 KB remain ... pool_size: 40.0 GB"

One query rejected cleanly beats one process killed silently.

The realistic path, in order

  1. Flip the Comet flag. Zero rewrite. 2.5×–2.6× measured, config only.
  2. Python cohort pilots DataFusion's own Python API on a query they already own. No Rust.
  3. Only if Comet's ceiling isn't enough, scope a hybrid: Spark orchestrates, DataFusion owns one hot step. Budget months, not weeks.
  4. Don't plan a full rewrite or a distributed rollout off evidence this thin.

Evidence-driven order, not dogma: measure which step hurts before deciding how much to replace.

Appendix: the budget returns itself

impl Drop for Reservation {
    fn drop(&mut self) {
        if let Some((control, bytes)) = &self.0 {
            let mut state = control.lock();
            state.bytes -= bytes;
            control.changed.notify_all();
        }
    }
}
